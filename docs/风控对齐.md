# 风控处理对照：biliTickerBuy main ↔ BiliTickerStorm

对照源：`mikumifa/biliTickerBuy` `main`（`task/buy.py`、`task/buy_helpers.py`、`util/request/BiliRequest.py`、`util/ErrorCodes.py`）。

## 已对齐

| 能力 | 上游 | Storm worker |
|------|------|----------------|
| prepare → createV2 字段/URL/ptoken/ctoken | `build_token_payload` / `prepare_create_request` | `BuildPreparePayload` / `ToCreateV2RequestBody` |
| 成功：`errno==0` 且无 `defaultBBR` | `is_create_success` | `isCreateSuccess` |
| 终端：`100003` / `100048` / `100079` | `CREATE_ORDER_TERMINAL_RULES` | `classifyCreateErrno` + 文案 |
| `100048` 暴露订单详情 | `orderDetail.html?order_id=` | `extractOrderURL` 同路径 |
| `100051` 回 prepare | `token_expired` | `CreateTokenExpired` |
| `100034` 更新 `pay_money` | 是 | 是 |
| `100001` 复检项目详情 | `handle_100001` + 预热 | `refreshProjectDetail`（GET 详情；H2 预热见 HTTP2_JA3） |
| HTTP 429 延迟后继续 | `rate_limit_delay_ms` | `RATE_LIMIT_DELAY_MS` |
| HTTP 412 → 代理失败/切换/冷却 | `handle_proxy_failure` | `handleProxyOrCooldown` + `ProxyPool` |
| 非 JSON 中的 412 | `status=412` 诊断 | `isNonJSON412` |
| 网络异常走代理失败 | `RequestException` → proxy failure | `handleTransportError` 非 429/412 也走代理路径 |
| 代理 API 补池 | `fetch_proxy_api` + `replace_proxy_pool` | `RefreshFromAPI` |
| 无极验主路径 | 主线无 geetest | 已移除 gt-python；`-401`/`100044` 记风险并重试 |
| errno 文案表 | `ErrorCodes.MESSAGES` | `errnoDict` |

## 有意差异（集群 / 阶段）

| 项 | 上游 | Storm | 说明 |
|----|------|-------|------|
| 代理全冷后 | `ProxyBackoff` **无限** 递增休息后继续 | 本地冷却 N 次后 **Risking**，任务回 Pending | 集群需换 worker；单机无限睡会占死节点 |
| HTTP/2 + JA3 + local_fanout | 可选 `ProxyPoolCreateV2FanoutJA3H2Client` | 未实现（`docs/HTTP2_JA3.md`） | fasthttp HTTP/1.1 |
| 100001 后 H2 预热 | `prewarm_h2_connection` | 仅详情 GET | 依赖 H2 客户端 |
| 页面 gate「立即购票」 | `wait_for_buy_button` | 未实现 | 迁移清单 §7 |
| 开售前预热 | `refresh_hot_and_warm` 在倒计时末 | 定时后直接 prepare | 可选增强 |
| 循环内随机 create 次数复检 | `refresh_interval_*` | 未实现 | 可选增强 |
| 支付二维码 / 多渠道通知 | 完整 | 仅 PushPlus 成功推送 | 产品范围 |
| create 批大小 | `create_request_batch_size` | 单次 create 循环 | 语义等价，无 fanout 批 |
| 412 响应体 | 返回 response 再 JSONDecode 判 412 | status 412 直接 `ErrRiskControl` | 等价；另补 body 文本 412 |

## 结论

**业务 errno 与 412/429/代理主路径已与上游对齐**；差异集中在：集群 Risking 降级、无 H2/JA3/page-gate、支付与多通知。后续若要对齐体验，优先 page-gate 与开售前预热，再评估 H2。
